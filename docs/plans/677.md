## 4. The design

### Voice split (`loom.voice.split`, MT-VOICE-02)

- **Added to** `crates/loom-modules/src/voice.rs`, beside Voice merge, and registered in `crates/loom-modules/src/lib.rs`.
- **Ports.** `in`: `SignalType::Audio`, `Channels::Voices`, default 0. `out1` to `out8`: `SignalType::Audio`, `Channels::PerChannel`, stereo when `in` is (rule 5 on `main`: a bundle-aware module's outputs take their sides from its first `Voices` input).
- **Parameter** `first`: `ParamSpec::integer`, 1 to 16, default 1, read per frame with `Param::map_or`. A number widget.
- **Each frame:** `outK` is voice `first + K - 1`, computed with `saturating_sub` so a bad value cannot underflow. If that voice is at or past `input_width(IN).voices`, the output writes `in`'s declared default, never a literal (ADR-0043), and `voice_input` is not called for it. So `first` at 16 on a 16-voice bundle reads voice 16 on `out1` and the default on `out2` to `out8`. Output sides loop over `output_width(OUT).sides`.
- No state, so `copy_state_from` and `reset` are the defaults.

### Voice spread (`loom.voice.spread`, MT-VOICE-03)

- **Ports.** `in` and `out`: `SignalType::Modulation`, `Channels::PerChannel`, `in` default 0.
- **Parameters.** `amount` (-10 to 10, default 0, `.smooth(0.005)`, `param_glide` as Add's `offset` does, control ranges by questions C and D), `mode` (Even, Series, Random; a segmented control), `seed` (1 to 65535, default 1, inspector only, `shown_when` Random). No `reset` input.
- It runs once per voice and reads `ProcessContext::voice` (1 to V) and `voice_count` (V).
- **Offsets.** All three are 0 when V is 1. Otherwise Even is `loom_dsp::blend::spread_offset(i - 1, V)`, the function the stack's spread calls; Series is `(i - 1)/(V - 1)`; Random is `2d - 1`, with `d` the first draw of `crate::rand::stream(seed, (i - 1) * 2, N)` for a stream number `N` no other module uses (ADR-0045). An offset of exactly 0 writes `in` unchanged.
- **Cache.** The offsets are cached with the voice, the count, and the rounded seed, and refilled only when one changes. `mode` is read per frame and picks among them.
- **Output.** `hold_finite(in + amount × offset)` for a finite `in`, and the plain sum otherwise.
- `mode` is matched with a fallback arm, never used as an array index.

### Value display from the selected range (item 12)

- `crates/loom-app/src/param.rs`, `param::format`: for a linear, non-whole-number parameter, 4 decimals when the selected range's span is under 0.1, else today's rules, which stay the floor. Whole numbers show none; logarithmic, decibel, and choice parameters keep today's rules. Arithmetic in f64; a span that is not finite and above 0 uses today's rules; at most 6 decimals.
- Callers: the tile (`scene.rs:585`, `:601`), the inspector row, a sub-patch surface (`surface.rs:461`), and the range note (`inspector.rs:759`). `controls.rs` `submit_value_draft` (`:500`) builds its unchanged baseline with the row's ranged spec (`node.spec(index)`, or the surface's exposed spec); `type_value_draft` (`:479`) keeps parsing with the descriptor spec, on purpose, since parsing does not round.
- The screen reader's description is the tile's shown text already; no change (L withdrawn).
- The rule is written into `docs/design/control-ranges.md`.

### The `loom-test` harness: voice and channel

- `crates/loom-test/src/lib.rs`: `Harness::voice(i, count)` and `Harness::channel(c)`, backed by a context-taking variant of `loom_core::testing::run_with_transport_and_channel` (`crates/loom-core/src/module.rs:896`), since a module with no `Voices` port runs through that path and it builds its own `ProcessContext`. ## 8. Risks

- **The value-display change is app-wide.** It is a floor on today's rules, so existing values show at least as many decimals, but snapshots that print values may change. The build runs the full app tests, updates any such snapshot on purpose, and lists it in the PR.
